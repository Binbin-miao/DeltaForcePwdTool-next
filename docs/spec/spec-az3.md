# Spec · AZ3 四类骇入小游戏（v6.0）

> 目标：v5 只认摩斯 / 指纹 / 旧操作台三种；AZ3 场景一律 `Unknown` → 拒绝执行。
> v6 在**不改动一级三分类**的前提下，给 Console 家族加一层二级变体判别，新增四条流程。
>
> 冻结时间：2026-11-14 ｜ 状态：**已实现（363 测试全绿 / clippy 零告警 / exe 5.82MB）**

---

## 1. 用户已拍板

| 编号 | 决策 |
|---|---|
| U1 | 四类一起做：大保险、任务保险、黄键台、信号线台 |
| U2 | 保险类全自动按空格（`0x39`），不做「只提示」 |
| U3 | 允许任务期间限时实时抓帧：最多 15s / 300 帧 ≈ 20fps，任务结束即 `Drop`，空闲零抓帧 |
| U4 | 黄键台：黄或绿亮起就直接点，点完等进度勾选 +1 |

## 2. 架构：一级 3 类不动，二级变体加一层

```
detect(frame) -> Morse | Fingerprint | Console | Unknown        （v5 原样，未改）
                                  │
                                  ├─ az3_variant(frame) 命中 → run_az3（四条新流程）
                                  └─ None                  → run_console（v5 旧操作台，原样保留）
```

理由：`Scene::ORDER [Scene;3]`、`scores [f32;3]`、`ADOPT_GAP=0.15` 是定长结构，
把 4 个近似界面塞进去会互相压分，恒判 `Unknown`；且 UI 六格开关是定长数组，会连锁改动。
二级判别用**有序证据**（强特征先排除），每类自己的阈值，互不压分。

### 2.1 二级判据（`crates/scene/src/lib.rs::az3_variant`）

按顺序：

1. **黄键台 `ModuleKeys`**：右侧网格黄/绿高亮占比 ≥ `0.004` 且能切出 ≥4 条等距竖列；
2. **任务保险 `SafePins`**：5 个配置槽里 ≥4 个槽内有细长竖直白块（高 ≥18px、宽 ≤10px）；
3. **大保险 `SafeTiming`**：目标带亮绿占比 ≥ `0.01` 且能切出 ≥3 条等距字符列；
4. **信号线台 `SignalLine`**：`az3.line_led_region` 内亮点占比 ≥ `0.01` 且 ≥7 个字符段；
5. 都不满足 → `None`（worker 回落旧操作台；旧操作台也判不出才 `Rejected`，零输入）。

## 3. 四条流程的判据

### 3.1 大保险 `flow-az3/src/timing.rs`

| 项 | 规则 |
|---|---|
| 找带 | 行投影找「高亮（绿或红）占比 ≥0.25」的连续行段，取均值最高的一段 |
| 找游标 | 带内**最大亮绿连通域**（面积 ≥12px），只取 `cx`；不用全带质心（会被绿底拉偏） |
| 格判定 | 格宽 = 带宽/5；`idx = (cx-x0)*5/带宽`，**中间格 idx==2** |
| 按空格 | 仅当「上一帧不在中格、本帧在中格」按一次；同一格停留不重复按 |
| 完成 | 按满 **5 次**（固定 5 字符）→ `Done` |
| 失败 | 带内红色占比 ≥0.30 → `Aborted("按早了，整条已变红")`；连续 8 帧找不到带 → Abort |

### 3.2 任务保险 `flow-az3/src/pins.rs`

- 轨道带内白色连通域：**游标**（高 ≥18、宽 ≤10）与**目标方块**（宽高 5–16）配对，同槽取最近一对；
- 激活槽 = 指示带里第一个未变绿的槽；
- `|游标x − 方块x| ≤ tol` 且**离开过容差区**才按空格（去重）；
- 5 槽全绿 → `Done`；连续 20 帧找不到目标 → Abort（不猜）。

### 3.3 黄键台 `flow-az3/src/keys.rs`

- 网格 4×4 等分，逐格统计黄/绿像素；选**未点过**且得分最高（≥40px）的格，点其几何中心；
- `clicked[16]` 去重；点后等进度勾选 +1，400ms 无变化则标 `dead` 换下一格；
- 进度区五等分统计绿色勾选；读到 5 → `Done`；16 格点完仍 <5 → Abort。

### 3.4 信号线台 `flow-az3/src/line.rs`

- 复用 `delta-flow-console` 的 4 列闭环（LED 解析 / 自举增益 / 列超时都已跑通），
  但几何换成 `az3.line_*`、色域换成「深蓝面板 + 暗红旋钮」；
- 失败文案带「可在设置→校准向导微调信号线台区域」。

## 5. 零值 / 空集边界

| 编号 | 条件 | 行为 |
|---|---|---|
| B1 | `target_band` 为空 / 连续 8 帧找不到带 | Abort，文案「未找到高亮带」 |
| B2 | 带内红色 ≥30% | Abort「按早了，整条已变红」 |
| B3 | 5 次空格未满就超时 | Abort，带「已按 N/5」 |
| B4 | 某槽找不到目标方块（连续 20 帧） | Abort「第 N 槽目标位未识别」，不猜 |
| B5 | 16 格全点过、进度仍 <5 | Abort「16 键已点完但进度未满」 |
| B6 | `az3_variant == None` | 回落旧操作台；旧流程也判不出 → `Rejected`，**零输入** |
| B7 | 抓帧配额（300）耗尽 | 留证 + `Failed("截图次数超限")` |
| B8 | 用户取消 | 每帧检查，边界处 `Aborted("已取消")`，不再发输入 |

## 6. 实机限制（必须先知道）

1. **需要正对面板**。几何是 1280×720 单机位实测的百分比；站偏了、蹲下、换 FOV 都会偏。
   每次任务 `logs/task_<ts>_<ok|fail>.png` 都会留下当时的整屏截图，用它调 `Az3Config` 即可。
2. **信号线台的列推进假设为「自动跳列」**（录像里玩家全程只转旋钮，没有横拖）。
   若不是，state machine 会走「等自动跳列」分支并最终 Abort，不会乱拖。
3. **任务保险的目标位**按「小白方块」识别；若实际是第二根游标，同样能配成一对（都是白色块）。
4. **黄键台高亮色**录像里是绿色，用户口述是黄色 —— 判据同时接受黄与绿
   （`r+g > 3b` 必须用 u16 比较：u8 在 `b ≥ 86` 时两边都饱和到 255，亮黄会漏检）。
5. **黄键台的 `ModuleKeys` 判定还要求网格里 ≥10 个暗色近方形键块**（gray < 90、宽高 15–80px）。
   这是为了不把旧操作台的米黄旋钮误当亮键。代价：如果实机按键底色偏亮（不是近黑），
   会识别不出 → 返回 `None`（安全失败，不会乱点），此时需要把 `AZ3_KEY_DARK_LUMA` 调高。

## 8. v6.2 变更（实机反馈驱动的两处关键修正）

### 8.1 信号线台改为**每帧自适应定位**（放弃固定百分比坐标）

固定坐标已证伪：用户实机同一台机器，旋钮中心在 `(0.604,0.554)~(0.766,0.573)` 之间漂，
用配置坐标算暖色占比 `t74=0.000 / t80=0.007 / t88=0.129 / t100=0.240 / t104=0.000`——时好时坏。

新实现 `crates/scene/src/locate.rs::locate_line`，按四步各自独立定位（任一步失败即零输入退出）：

1. **旋钮**：全帧找暗红圆（H 0-14/170-180、S≥90、V≥70），取最大且 300..8000px、宽高比 0.55..1.8、填充率≥0.45 的连通域；
2. **LED**：旋钮上方找「亮底暗字」长条（Otsu 前景 0.02..0.30、7~11 个字符段、宽高比≥3）；
3. **屏幕**：旋钮左侧找青色边框（H 80..100、S≥60、V 60..200）最大矩形；
4. **4 列 + 档位**：屏幕内白色列投影取 4 峰，每列行投影取 4 个档位中心。

操作改成**只上下拖 + 列自动推进**（不再横拖切列），完成判据双保险：
4 列档位在目标行停满 600ms，**或**出现黄黑斜纹「信息已校准」。

看不出某列档位（实测第 4 列常被屏幕右缘裁掉）→ 该列判死跳过，其余列照拖，
收尾时明确报「第 N 列没能对齐」，不再因一列读不到就整体放弃。

### 8.2 截图黄框与误判

- **屏幕四周闪黄框**：WGC 每次建会话时 Windows 画的「正在捕获」边框。
  已在 `crates/capture/src/wgc.rs` 调 `GraphicsCaptureSession::SetIsBorderRequired(false)` 关闭
  （Win11 22H2+ 生效；旧系统/策略禁止时调用失败但不影响抓帧）。
- **窗口外框呼吸**：`crates/ui/src/view.rs::paint_shell` 原来在运行态沿窗口画 2px 橙色呼吸描边、
  未识别 2Hz 硬闪。已删除，状态只由标题栏 7px 状态点表达。
- **摩斯界面被误判成信号线台并拖了 64 个输入事件**：`console_score` 增加「暖色旋钮」硬证据
  （`knob_score`，旧台米黄 / AZ3 暗红都命中；摩斯界面实测 0.0000）。
- **每次按 F 都留证**：`logs/task_<时间戳>_<ok|fail>.png/.txt`，自动只保留最近 40 组。

## 9. v6.4 变更：分辨率归一化（实机 1080p 全废的根因）

实机日志（`logs/task_*_reject.txt` 38/38 条）全部是 `场景: Unknown, AZ3: None`，
而截图里明明是黄键台（屏幕写着「进入手动操作模式 / 需要操作的模块即将高亮 / 请输入 /
自动破译进行中 0%」，右侧 4×4 图标键）。逐帧实测查出**两个独立缺陷**：

### 9.1 像素阈值是 720p 绝对像素，1080p 下全超限

- 实机屏 1920×1080，16 颗键实测 **86×83 px**；判据 `KEY_SIDE = 18..70` ⇒ 全部被滤掉；
- 旋钮面积 `KNOB_MIN_AREA..KNOB_MAX_AREA = 300..8000`、屏幕降采样格数 `800`、
  LED 面板 `6000`、游标高 `18`、目标方块 `5..16`、高亮像素 `40`、勾选像素 `10` —— 同类问题。

**修法不是逐个乘系数**（几十处、必漏），而是把帧统一归一到 720p 世界判定：

- `locate::normalize_frame(frame) -> (Frame, scale)`：等比缩放到高 720，
  返回「原图/缩放」比例；幂等（≤720 原样返回）；
- `locate_line` / `locate_keys` 内部先归一化，输出的**所有坐标乘回 `scale`**，
  于是调用方拿到的永远是真实屏幕坐标；
- `az3_variant` 入口同样归一化（判别层的阈值也是 720p 口径）；
- 只抓小区域的流程（大保险抓高亮带、任务保险抓滑槽）不能按帧高缩 ——
  用 `locate::denormalize_region(frame, scale)` 按**全屏比例**缩，
  阈值用 `flow_az3::{screen_scale, scaled_len, scaled_area}` 放大。

### 9.2 黄键台把「颜色」当成了判别条件（反指标）

旧前置过滤要求「全帧黄/绿高亮占比 ≥ 0.001」。实测：

| 画面 | 占比 | 旧过滤 | 实际 |
|---|---|---|---|
| 真黄键台（刚打开，0%，一颗没亮） | **0.000000** | 拒绝 | 应该识别并等它亮 |
| 真黄键台（屏幕提示行有绿色三角） | 0.000794 | 拒绝（差一点） | 应该识别 |
| 场景里的终端机 + 黄色按钮 | 0.005030 | 通过 | 不该识别 |

**高亮是执行期才出现的东西，只能用来选键，不能用来判别界面。**
已删除该过滤，改由结构证据判别：`locate_keys` 能找到 4×4 暗键阵
+ 左侧暗屏 + 键阵宽高比落在 `0.72..1.40`（排除墙面长条暗格阵）。

### 9.3 进度格读不出来 → 改用「亮光熄灭」做 ack

实机屏幕整体极暗（luma 中位数 48，95 分位 101），5 个输入格与背景的亮度差只有 5~10，
**任何绝对阈值都分不开**（实测 `progress = 0`）。旧实现只认「进度 +1」，
读不到就退化成「16 格点完才算完」—— 会多点一倍以上。

新增判据：**点对了游戏会收掉该模块的高亮**。这条通道永远可用：

1. 进度推进（能读到进度框时最可靠）；
2. **该格黄/绿像素跌破 `min_glow / 2`** ⇒ 视为吃下，立刻可以点下一颗；
3. 一直亮着超过 400ms ⇒ 这一格点错/无效，判死换下一颗。

顺带修两处收尾：16 格耗尽且读不到进度 → 报失败而非「完成」；
**点过键之后面板消失 ⇒ 判定完成**（否则每次成功都会被报成「找不到 4×4 按键阵」失败）。

### 9.4 附带修正

- `KEY_BOX_ASPECT` 下限 `1.2 → 0.75`：实机进度格是 70×77px 的近方形（0.91）。
- 实机 1080p 三帧核对：`locate_keys` 全部 `Ok`（`grid` 990,314 386×383 / 16 格齐），
  `az3_variant = ModuleKeys`；跑图帧正确 `None`。
