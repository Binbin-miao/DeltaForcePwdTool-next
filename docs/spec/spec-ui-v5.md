# Spec v5.0 — F 键触发 / 符号热键 / 界面重做

> 用户原话（2026-11-09）：
> ① 「我现在想要的是可以按 f 键自动识别」
> ② 「要像（老版本截图）我之前一样支持符号等按键」
> ③ 「指纹在不同分辨率下会有所不同所以之前才需要模糊匹配+置信度，我的模板是 1080p 下截取的」
> ④ 「现在的 ui 界面太丑了，重新做过一版」→ 后续拍板：「用 uiA，但是不要上面的目标序列和格子，还有我之前 cfg 文件里面可以配置的是否自动点击和是否自动点击下载给我加上」

## 1. 已拍板决策与显式边界不变量

- **[D1] UI 用方案 A（任务卡）骨架，并移除顶部「目标序列」区与 4 个格子。**
  用户明确要求删除该区。释放的垂直空间正好容纳 D2 新增的两行开关，**窗口尺寸保持 400×420 不变**（现有 4 条几何断言的基线不推翻）。
  边界：删除后**识别结果必须有落点** —— 主按钮下方那一行作为结果/状态行：空闲显示「· 就绪」，成功显示识别结果（摩斯密码或点击顺序），失败显示红色原因。**不允许**出现「识别完了但用户看不到结果」。

- **[D2] 开关共 5 个，排成 3 行 × 2 列网格，第 6 格放热键键帽。**
  用户拍板「双列 3×2 网格」。开关区从单列 5 行（160px）压到 108px，省出的 52px 全部给结果区，使识别结果能以 26px 等宽大字显示。

  | 格位 | 内容 | 绑定字段 | 默认 | 上游对应 |
  |---|---|---|---|---|
  | ① 左上 | 摩斯解码 | （现有流程开关） | 开 | — |
  | ② 右上 | 指纹识别 | （现有流程开关） | 开 | — |
  | ③ 左中 | 操作台 · BETA | （现有流程开关） | 开 | — |
  | ④ 右中 | 指纹自动点击 | `fingerprint_auto_click`（`crates/config/src/lib.rs:85`） | 开 | `fingerprint_auto_click` |
  | ⑤ 左下 | 摩斯自动下载 | `auto_confirm`（`crates/config/src/lib.rs:81`） | 开 | `morse_auto_click` |
  | ⑥ 右下 | 键帽 `F8`（不可点，显示当前热键） | — | — | — |

  文案依据：上游 `core/morse.py:104` 打印的正是「→ 点击下载」，故⑤命名为「摩斯自动下载」而非「自动确认」。
  边界：④⑤ 的关闭语义必须**立刻生效于下一次识别**，不得要求重启；关闭后必须**真的不点击**（`flow-morse` 的 `MorseRun.auto_click` 与 `flow-fingerprint` 的点击分支都已支持该布尔，只需接线）。

- **[D2b] 结果是三场景共用的，不是操作台专属。**
  用户问「那摩斯密码和指纹密码呢」——三种场景识别完都有结果，**同一个结果区**承载：

  | 场景 | 结果区主内容（26px 等宽） | 右下状态标签 |
  |---|---|---|
  | 摩斯 | `4 2 7` | `已输入` / `已识别·未输入`（关闭自动下载时） |
  | 指纹 | `1 → 3 → 5`（点击顺序） | `已点击` / `未点击`（关闭自动点击时） |
  | 操作台 | `01 · 00 · 01 · 11`（目标序列） | `已拖 3/4 列` |

  「目标序列」只是操作台那一种的叫法，**不得**因此把它做成操作台专属区块。用户已确认保留该信息（放在共用的结果区里），不恢复顶部独立序列区。

- **[D3] F 键用低级键盘钩子（`WH_KEYBOARD_LL`），回调只投递事件、绝不采集。**
  用户拍板选「键盘钩子（老版做法）」，理由是 RegisterHotKey 注册单键 F 会**吞掉游戏的 F 交互键**。
  强制边界：
  1. 回调内**只允许**做「读 `vkCode` → 判断是否 F → 比对前台窗口标题 → 向主线程投递一个事件」，**禁止**截图、识别、文件 IO、锁等待。任何耗时操作都会拖慢全系统键盘输入。
  2. 回调**必须**返回 `CallNextHookEx`，**绝不吞键**（游戏要能收到 F）。
  3. 钩子**必须可关**：设置里提供总开关，关掉即卸载钩子，F 键完全不受本程序影响。
  4. 关闭钩子后**不得**回退成 `RegisterHotKey("F")` —— 那会吞键，等于把用户的游戏交互搞坏。关闭 = 完全不监听 F，用户改用其它热键。
  5. 仅在**游戏窗口处于前台**时响应（判据：前台窗口标题包含配置里的关键词，默认 `["三角洲", "Delta Force"]`，可在设置里增删）。非前台时静默忽略，不消耗任何截图配额。

- **[D4] 符号键走 `RegisterHotKey`（与 F 键的钩子并存，互不影响）。**
  理由：游戏不使用 `/`、`` ` `` 这类键，`RegisterHotKey` 注册它们不会影响任何游戏操作，且实现简单、可靠。
  扩展 `crates/app/src/platform.rs` 的 `KEY_TABLE`（当前 71 项，仅 F1~F24 / A~Z / 0~9 / Space / Insert~PageDown / 方向键），新增 11 个 OEM 键：
  `Slash`(0xBF) `Backslash`(0xDC) `Semicolon`(0xBA) `Quote`(0xDE) `Comma`(0xBC) `Period`(0xBE) `Minus`(0xBD) `Equal`(0xBB) `BracketLeft`(0xDB) `BracketRight`(0xDD) `Backquote`(0xC0)。
  `delta_ui::state::CAPTURABLE` 必须同步扩容（`platform.rs:497-501` 的双向断言会强制这一点）。

- **[D5] 模板匹配算法一行不改。**
  已核对：`crates/templates/src/matching.rs` 是上游 `core/fingerprint.py:73-96` 的逐行移植（模板非等比 `resize` 到候选格尺寸 → 取中心 70% → `TM_CCOEFF_NORMED` 滑窗），`MIN_SCORE = 0.45`（`crates/templates/src/vote.rs:155`）与上游 `threshold: float = 0.45` 完全一致。模板尺寸在匹配前被丢弃，只保留图案比例，**1080p 模板在 2K 上天然可用**。
  边界：**禁止**引入多尺度搜索、CLAHE、直方图均衡等"增强"——它们会让现有 54 张模板与 33 条操作台用例全部重新基线，且无实测证据支持。

- **[D6] 符号键与 F 钩子是两条独立通道。**
  符号键（D4）= 用户主动按的"强制指定"热键（如 `/` 跑摩斯）；F 钩子（D3）= 游戏内交互键的旁路监听（自动判别）。
  两者同时存在，互不阻塞；任一触发都应走同一条 `run_once` 入口，共用 20 张截图配额。

- **[D7] 六套配色全部保留，可在设置里切换；默认用浅色。主色可自定义。**
  用户明确要求「为什么不能都加进去呢」——不做取舍，**六套全是 `ThemeId` 的预设成员**：

  | ThemeId | 名 | 深浅 | accent | 气质 |
  |---|---|---|---|---|
  | `Graphite` | 石墨 | 深 | `#E8EBEA` | 无彩色，靠留白，最耐看 |
  | `Nightwatch` | 夜航 | 深 | `#4C8DFF` | 深蓝黑 + 电蓝，最商业 |
  | `Ember` | 暗焰 | 深 | `#FF9E3D` | 暖褐 + 橙，最贴游戏现场 |
  | `Paper` | 素纸 | 浅 | `#2C3E6B` | 米纸 + 墨蓝，印刷品气质 |
  | `Frost` | 霜白 | 浅 | `#1C2024` | 冷白 + 近黑，最锐利 |
  | `Celadon` | 瓷青 | 浅 | `#1F6B4F` | 浅灰绿单色，最安静 |

  用户拍板「默认浅色」→ **默认 `ThemeId::Frost`（霜白）**，写入 `Config.theme_id` 的 serde 默认值；旧配置缺该字段时回落到 Frost 而不是深色。
  边界：
  1. 切换主题**不得重启**（`Context::set_visuals` 仅作原生控件兜底，自绘控件以 `Palette` 为准）。
  2. **主色可自定义**（用户选「可改主色」）：任意色相经 OKLCH 派生，深色主题恒用深字（实测对比度 7.1–8.1:1）、浅色主题恒用白字（6.15–7.01:1）；chroma 越界按 0.93 步降。状态色（ok/warn/err）**不跟随** accent。
  3. 完整色板与派生规则见 `docs/design/ui-themes.md` §2（六套各 14 项 token）与 §2.7（自定义规则）——**实现时逐项抄，不得自创颜色**。
  4. 布局用 `ui-themes.md` §3.1 的 L-A（双列开关 · 单卡主体），纵向分段见该节表格（合计 404 = 420 − 上下 8px 边距）。
  5. 五状态与按钮谓词必须照 `ui-themes.md` §3.4 实现：**Idle 不画空卡**、按钮 `enabled = 已校准 && 至少一开关开`、不满足时**改文案**而非静默禁用。

### 2.1 布局预算（已核算，批 2 直接照此排，不要再问）

现有常量（`crates/ui/src/theme.rs:80-85`）：`TITLE_BAR_H=32`、`SEQUENCE_H=72`、`TOGGLE_H=28`、`PRIMARY_H=36`、`PROGRESS_H=64`、`FOOTER_H=28`；间距 `SPACE_XS=4`、`SPACE_S=8`、`SPACE_M=12`。

删除 `SEQUENCE_H`（72）并新增 2 行开关（2 行 × (28+4) = 64）→ **净腾出 8px**，因此 **400×420 不需要改窗口尺寸**。

排布（相对窗口顶部，content 已 shrink `(12, 8)`）：

| 区块 | 纵向区间 | 高度 |
|---|---|---|
| 标题栏 | 8 ~ 40 | 32 |
| 开关 1 摩斯解码 | 52 ~ 80 | 28 |
| 开关 2 指纹识别 | 84 ~ 112 | 28 |
| 开关 3 操作台 BETA | 116 ~ 144 | 28 |
| 开关 4 指纹自动点击 | 148 ~ 176 | 28 |
| 开关 5 摩斯自动下载 | 180 ~ 208 | 28 |
| 主按钮「开始识别 F」 | 212 ~ 248 | 36 |
| 结果 / 进度区 | 256 ~ 320 | 64 |
| 底部链接 | 约 364 ~ 392 | 28 |

**余量约 68px**（320~364 之间），可用于把结果行做得更醒目或容纳 notice 条。

最小尺寸 340×360 下高度少 60px：**优先压缩 `PROGRESS_H` 到 44**，不要压 `TOGGLE_H`（28 已是可点击下限），也不要删行。压缩后仍溢出则把开关行间距从 4 降到 2。

## 4. 验收门禁清单

- [ ] `KEY_TABLE.len() == CAPTURABLE.len() == 82`，双向 `parse → format → parse` 往返通过
- [ ] `parse_hotkey("/")` == `Ok(Hotkey::plain(0xBF))`；`format_hotkey` 能还原成 `/`
- [ ] 钩子安装后：模拟 F 键 → 触发一次 `run_once`；**且 F 键仍传递给下一个钩子**（`CallNextHookEx` 返回值非 0）
- [ ] 钩子关闭后：按 F **无任何反应**，且**没有** `RegisterHotKey("F")` 残留（否则吞键）
- [ ] 非游戏前台按 F：零响应、零截图、零配额消耗
- [ ] 关「指纹自动点击」→ 流程产出标注图但 `clicked == false`
- [ ] 关「摩斯自动下载」→ 输入完密码但不点确认，`ConfirmSkipped` 有对应原因
- [ ] 主界面在 400×420 与最小 340×360 下：5 行开关 + 主按钮 + 结果行 + 底部链接全部可见，结果行不压底部按钮
- [ ] 识别成功时结果行显示实际结果（非空）；失败时显示具体原因
- [ ] `cargo test --workspace -- --test-threads=1` 全绿（基线 304，预计 +12~18）
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` 零告警
- [ ] `cargo build --release` 产出 exe，体积 ≤ 8MB

## 5. Non-Goals（本轮明确不做）

- **不改模板匹配算法**（见 D5，无证据不动）
- **不做常驻轮询截图**（D3 的钩子只在按键瞬间投递事件，不产生任何周期性采集）
- **不恢复目标序列区**（用户明确删除）
- **不改窗口尺寸**（保持 400×420；若 5 行确实放不下，允许把窗口高度放宽到 460，但必须同时更新 4 条几何断言并在报告中说明）
- **不引入第三方 crate**（钩子用现有 `windows` crate）
- **不做主题切换**（浅色/深色二选一，本轮保持深色）
