# t6 — `delta-ocr`（Windows 系统 OCR，零体积）

**独占写锁**：`crates/ocr/**`
**依赖**：t1
**规格**：`../spec.md`（D2，§6 风险）

## 任务
1. `OcrEngine::new(lang: &str) -> Result<Self, OcrError>`：
   - 在**独立的 MTA 线程**上初始化 COM（`CoInitializeEx(COINIT_MULTITHREADED)`），该线程常驻并持有引擎（浮光结论：OCR 会绑线程，必须专用线程）；
   - 语言默认 `zh-Hans-CN`，回落到 `zh-CN`，再回落到系统默认第一项；全部失败返回 `OcrError::NoLanguage`；
   - 构造 `OcrEngine` 前必须 `Initialize` WinRT。
2. `pub fn recognize(&self, frame: &Frame) -> Result<String, OcrError>`：
   - `Frame`(BGRA) → `SoftwareBitmap`（`BitmapPixelFormat::Bgra8`、`BitmapAlphaMode::Premultiplied`）→ `SoftwareBitmap::Create` 的内存路径；
   - 调 `RecognizeAsync` 并用 `.get()` 阻塞取结果（在专用线程内，绝不阻塞 UI 线程）；
   - 拼接所有 `OcrLine.text`，行间用空格，去首尾空白。
3. 可用性探测：`OcrEngine::is_available()`（一次性缓存结果），供 UI 展示"OCR 兜底：可用/不可用"。
4. 降级契约（D2）：引擎不可用或超时（>500ms）时返回 `OcrError`，**调用方必须能继续跑**（指纹流程退回纯模板投票），不得 panic。
5. 单元测试：`is_available()` 不 panic；不可用语言名返回 `NoLanguage`；用一张合成中文图（若引擎可用）断言包含预期字符，不可用时该测试 `#[ignore]`。

## 验收

```bash
cargo test -p delta-ocr
cargo clippy -p delta-ocr -- -D warnings
```

## 禁止
- 不要引入 `tesseract`/`ocrs`/`rapidocr` 等模型依赖（D2 已定：零模型）。
- 不要在此 crate 做名字纠错（那属于 flow 层）。
- 不允许把 COM 初始化放在 UI 线程。
