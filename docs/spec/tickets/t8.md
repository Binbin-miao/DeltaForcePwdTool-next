# t8 — `flow-console`（操作台旋钮闭环状态机）

**独占写锁**：`crates/flow-console/**`
**依赖**：t2、t3、t5
**规格**：`../spec.md`（D7、D8，**§2.3 状态机全文 + 自举表**，§4 操作台门禁）

这是本轮最难的一块。用户明确说过「部分得进游戏实测才清楚」，所以**所有未知映射都必须运行时自举，禁止写死任何像素常数**。

## 任务
1. 实现 `spec §2.3` 的完整状态机：
   - 状态 `Idle / Detect / Parse / Plan / ColumnAlign / RowAlign / Dwell / Verify / Done / Aborted`；
   - 每状态有明确超时（Parse 3s、单列 12s、全局 90s）；
   - **Done 主判据 = 面板青色结构特征占比 <8%**（面板整体消失，见 spec §7.4），**辅助判据 = 局部黄黑斜纹浮层出现**（仅表示「该列已接受」，见 §7.3，**不可当全局完成**）；
   - 任一完成信号命中后**立即停止一切输入**（断言事件计数不再增长）。
2. `Parse`：读 LED 4 组（`vision::read_led_sequence`，仅 `0/1/-`），读黄块位置 `(col, row)`（在 `panel_region` 内用 HSV 阈值找米黄色块，取质心；阈值进配置）。
3. `Plan`：`col_x[4] × row_y[4]` 来自配置（百分比），把目标序列映射到行索引。**方向映射（序列左端↔最左列）首次由 `Plan` 假设，首列成功后用实测结果校正并缓存**。
4. `ColumnAlign`：黄块不在目标列 → 横向 `Drag::step`（初值 ±12px，分 3 次小步），每步后重捕获；
   - **列索引未变** → 判定该游戏不支持横拖切列，切「等自动跳列」分支（轮询 200ms，最多 3 次）；
   - 列已变 → 进 `RowAlign`。
5. `RowAlign`：纵向小步拖动（初值 ±10px），每步后重捕获黄块 Y；
   - **自举方向**：首次试探后比较 ΔY 与拖动方向，反向则取负；
   - **自举灵敏度**：记录 `dy_panel / dy_mouse` 作为本会话增益，后续步长按 `剩余距离×增益` 反算，夹在 `[4, 20]px`；
   - `|ΔY| ≤ row_tolerance`（默认 6px，进配置）→ `Dwell`；
   - 步数超 `max_steps`（默认 60）→ `Aborted`。
6. `Dwell`：松开鼠标后静置 `dwell_ms`（默认 900ms）。
7. `Verify`：重捕获 →
   - 面板消失（青色占比 <8%）→ `Done`（立即停手）；
   - 斜纹浮层出现 → 该列已被接受 → 回 `ColumnAlign`（下一列）；
   - 列索引推进 → 回 `ColumnAlign`（下一列）；
   - 无变化 → 该列重试（≤3 次），每次 `dwell_ms += 300`（上限 2400）；
   - 超重试 → `Aborted`。
8. `Aborted` **禁止自动重试**，必须靠用户再按键重入（防失控连点）；返回结构化原因（`ParseFailed / DragNoEffect / DwellTimeout / StepOverflow / GlobalTimeout`）。
9. 首拖无反应 → 先点 `panel_region` 中央取焦，再重试一次（只做一次）。
10. 单元测试（用注入的假 `Capturer` 与假 `Drag`，不碰真实屏幕）：
    - 正常 4 列通关路径；
    - 中途出现斜纹 → 立即 `Done` 且零后续输入；
    - 拖动无效（黄块 Y 不变）→ 触发取焦重试 → 再无效 → `Aborted`；
    - 全局超时 → `Aborted`；
    - **零值边界**：LED 读到 `` 或不足 4 组 → `ParseFailed`，不得进入拖动。

- 不要在此层实现截图/匹配/输入原语。
