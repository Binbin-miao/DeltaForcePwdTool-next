# Spec 样本采集 — AZ3 两种操作台识别

## 0. 背景与已确认事实

- 用户实测反馈：AZ3 场景里存在**两种不同的操作台**，当前 v5 版本**必定报错**，无法识别也无法操作。
- 现有操作台实现（`crates/flow-console`）只覆盖视频素材里那一种布局：面板青色占比判完成、4 列 × 4 行网格、LED 目标序列读 `01-00-01-11`、旋钮拖拽对齐。
- 推测的失败原因（**待样本证实，不作结论**）：
  1. 场景判别（`crates/scene`）不认这两种界面 → 判成 `Unknown` → `is_actionable()==false` → 拒绝执行；
  2. 或判成 `Console` 但面板特征（颜色/网格/列数/行数）与内置参数不符 → 状态机在 `Detect` / `Parse` 阶段中止；
  3. 也可能是 LED 目标序列的字符集或排布不同 → `LedAmbiguous` / `LedNoAnchor`。
- **没有样本之前不允许改识别算法。** 本轮只解决「把样本完整、可分析地拿到手」。

---

## 1. 已拍板决策（2026-11-14）

- **[D1] 采集工具用现成方案：OBS Studio 录屏 + Keyviz 输入浮窗。** 不为采集单独开发软件。
  - 理由：需要从录像里判断的是「界面长什么样 / 操作顺序 / 成功失败判据」，这三项靠画面即可获得，不需要毫秒级坐标时间轴。
  - 显式边界：若后续发现必须精确坐标（例如要标定拖拽步长与灵敏度），再评估自研采集器；本轮不做。

- **[D2] 样本覆盖面：两种操作台 × 多种情况，成功与失败都要。**
  - 用户明确选择「多录几次不同情况」，因此不接受只录一次成功流程。

- **[D3] 本版目标：能认出来 + 能操作。** 两者冲突时优先保证「不乱报错」。

- **[D4] 录像硬性技术要求（缺一项则样本作废）：**
  1. **鼠标光标必须出现在画面里**（OBS 显示器采集默认不录光标，必须手动勾选）；
  2. 操作台界面**完整入画**，不允许只录局部；
  3. 每段录像**开头与结尾各静置 ≥2 秒**，开头用于看清初始布局，结尾用于看清结果反馈；
  4. 录像**不做剪辑、不加字幕、不加速**，原样提交；
  5. Keyviz 浮窗**不得遮挡操作台**（放屏幕角落），且必须能看清按下的键与鼠标点击。

## 2. 采集清单（逐条打勾，缺项会导致分析不完整）

| # | 内容 | 目的 | 是否必须 |
|---|---|---|---|
| S1 | 操作台 A：完整成功流程（开头静置 2s + 操作 + 结尾静置 2s） | 建立该变体的基线：布局、列数、行数、目标序列位置 | 必须 |
| S2 | 操作台 A：软件报错的那次完整过程（含报错提示出现） | 确认失败发生在哪一步（判别/解析/对齐/验证） | 必须 |
| S3 | 操作台 B：完整成功流程 | 与 A 对比，找出两种变体的差异点 | 必须 |
| S4 | 操作台 B：软件报错的那次完整过程 | 同上 | 必须 |
| S5 | 操作台 A：换一组不同目标序列（至少再 1 次） | 排除「只有某组序列才失败」的偶然性 | 必须 |
| S6 | 操作台 B：换一组不同目标序列（至少再 1 次） | 同上 | 必须 |
| S7 | 若任一变体会出现「面板中途消失」或「斜纹浮层」 | 验证完成判据是否通用 | 出现则录 |
| S8 | 游戏内 UI 缩放比例、分辨率（口头说明或录设置界面） | 判断是否与内置坐标基准不符 | 建议 |

> 命名建议：`A_成功_01.mp4`、`A_报错_01.mp4`、`B_成功_01.mp4`……放进同一个文件夹整体提交。

## 3. 收到样本后的分析步骤（主理人执行）

1. **先判失败层级**：逐帧看 S2 / S4，确认报错前最后一帧的操作台是否被完整截到、面板颜色是否与 `ConsoleParams` 的青色阈值相符。
2. **提取两种变体的差异矩阵**：列数、行数、单元格间距、旋钮外观、LED 区位置与字符宽度、是否有额外装饰元素（斜纹/边框/文字）。
3. **对齐现有参数**：把差异逐项对照 `crates/flow-console/src/params.rs` 的阈值，判断是"参数不同"还是"结构不同"。
4. **判断工作量分档**：
   - 参数不同 → 加一套参数档位（小改）；
   - 结构不同（列数/行数变化）→ 状态机需泛化（中改）；
   - 规则不同（不是拖旋钮对齐）→ 需新增流程（大改，另开工单）。
5. **落盘新 spec**（`spec-console-variants.md`）后再动代码。

---

## 4. 验收标准（本轮采集）

- [ ] S1~S6 六段录像齐全，命名规范，同一目录提交
- [ ] 每段都能在画面上看到鼠标光标位置与拖拽方向
- [ ] 每段都能看到 Keyviz 显示的按键/点击
- [ ] 开头结尾各 ≥2 秒静置
- [ ] 至少有一段包含软件报错的完整提示

---

## 5. 明确不做（Non-Goals）

- 本轮**不修改** `crates/scene`、`crates/flow-console`、`crates/vision` 的任何识别逻辑。
- 不开发自研录屏/采集器。
- 不根据推测提前给两种变体写参数（没有样本的标定等于猜）。
